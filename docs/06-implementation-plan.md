# 实施计划与验收

## 当前完成情况（2026-08-02）

- **阶段 0：完成。** 项目、文档、GitHub 仓库、TypeScript/Vite 构建基线与规则研究已建立。
- **阶段 1：完成。** 正式美术资源、四张核心界面稿、动态 React 牌桌与视觉验收均已完成。
- **阶段 2：进程内核心完成。** 权威纯 TypeScript 比赛状态机、Intent/Event、查看者快照、AI 同接口和本地适配器已经落地，并跑通完整 8 轮快速局。
- **阶段 3：尚未开始。** Node.js/WebSocket 权威房间服务、好友房生命周期、Redis、重连和分享令牌尚未编码。
- **阶段 4：尚未开始。** 正式 Cocos Creator 3.8 微信小游戏工程、微信能力接入、部署和真机发布尚未开始。

React/Vite 版本仍是交互与架构验证工具。当前状态机虽然具备权威语义，但仍运行在浏览器进程内；不得将其描述为已经上线或已经联网的服务端。

## 本轮已实现

### 权威比赛状态机

- 新增 `AuthoritativeMatchState`，集中持有轮次、发牌者、手牌、王牌、叫墩、当前一墩、分数和版本；
- 新增 `MatchIntent`、`MatchEvent` 与 `MatchTransition`；
- 实现命令 ID 首次结果缓存/重放、状态版本检查、阶段检查、行动者检查与稳定错误码；
- `MatchIntent` 不再信任客户端自报玩家 ID，行动者由适配器会话注入；
- 实现翻牌后固定王牌、无王牌或发牌者选择王牌；
- 实现全员叫墩、合法牌集合、完整一墩出牌与胜者判定；
- 实现一墩结束后的下一领出者、整轮结束后的计分与累计分；
- 实现下一轮发牌者顺时针轮转；
- 实现完整 8 轮快速局和比赛结束总榜。

### 查看者快照与 AI

- `createPlayerSnapshot` 从公共快照移除全部手牌、已处理命令 ID 与命令结果缓存；
- 公共状态只保留各座位手牌数量；
- 私有状态只包含当前查看者手牌和当前合法牌 ID；
- 快照内卡牌、玩家、墩和计分条目与权威状态隔离复制；
- AI 使用与真人相同的查看者快照、意图和状态机入口，不获得额外私有信息；
- 当前启发式 AI 可以选择王牌、叫墩并完成合法出牌。

### 本地适配器与动态牌桌

- `useLocalMatch` 作为临时本地适配器，在同一浏览器进程中驱动真人和 AI；
- React controller 只暴露查看者快照，不再暴露完整 `AuthoritativeMatchState`；
- 带随机源的跨轮转换在 reducer 外计算，避免 Strict Mode/并发重放重复消耗 RNG；
- 选择王牌、叫墩与出牌均显示 30 秒倒计时，超时通过同一 Intent 接口托管本次行动；
- 动态牌桌根据快照渲染六席、发牌者、AI 标识、手牌数和角色表情；
- 已实现动态叫墩面板、王牌选择面板、合法/非法牌、手牌选择与确认出牌；
- 已实现当前一墩、赢墩反馈、羊皮卷轮结算、继续下一轮和快速局总榜；
- 已实现 3–6 人查看者相对座位映射，以及 `844×390` 短横屏不溢出的布局；
- 当前牌桌由可拆分组件和正式美术资源组成，可迁移为 Cocos Scene/Prefab，而不是依赖整屏截图热点。

## 验收矩阵

### 当前进程内闭环

- 规则：叫墩、王牌、合法牌、一墩胜者、轮分和总分由同一权威状态机产生；
- 隐私：React controller、人类与 AI 都通过查看者快照读取状态，不直接消费完整手牌表；
- 流程：六席可完成叫墩、整轮出牌、轮结算、发牌者轮转和 8 轮快速局；
- UI：动态牌桌能表现当前行动者、30 秒倒计时、合法牌、一墩、轮结算和总榜，并通过桌面/短横屏 Design QA；
- 边界：React 只作为验证工具，不承担正式联网权威。

### 正式体验版待验收

- 网络：重复、乱序和陈旧意图不会造成分叉；
- 隐私：任何网络事件或恢复快照都不暴露其他手牌或牌库顺序；
- 弱网：普通网络重连后目标 3 秒内恢复；
- 体验：快速局约 12–18 分钟，核心行动无需打开二级页面；
- 设备：至少两台 iPhone、两台 Android，窄屏与长屏均不遮挡核心按钮；
- 性能：目标设备保持不低于 30 FPS；
- 视觉：最终 Cocos Design QA 无 P0/P1/P2 问题。
