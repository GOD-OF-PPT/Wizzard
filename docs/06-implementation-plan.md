# 实施计划与验收

## 阶段 0：项目基线

- 固化规则、视觉方向、技术边界与资料来源；
- 建立 TypeScript、构建与 GitHub 仓库；
- 保存原始规则照片和选定视觉稿。

完成条件：`npm run typecheck` 与 `npm run build` 通过，initial commit 已推送。

## 阶段 1：美术资源与交互原型

- 完成牌桌背景、四花色、卡背、特殊牌、六个头像和基础控件资源；
- 按 16:9 还原选定视觉；
- 实现手牌选择、合法牌状态、预测面板、王牌面板和一墩演示；
- 在同一画幅进行视觉对比 QA。

## 阶段 2：规则引擎

- 使用测试驱动方式逐步实现牌组、发牌、王牌、预测、合法出牌、赢墩、计分和模式轮数；
- 覆盖特殊牌领出、多张至高牌和全虚无牌等边界；
- 每种人数和模式至少自动模拟 1,000 局。

## 阶段 3：好友房与 AI

- 实现权威 WebSocket 房间服务；
- 完成分享令牌、房间码、准备、AI 补位、超时托管与重连；
- 验证重复命令、乱序、切后台和房主退出。

## 阶段 4：微信体验版

- 将经过验证的牌桌迁入微信小游戏客户端；
- 配置横屏、登录、分享、合法域名和腾讯云托管；
- 添加体验成员并完成真机测试。

## 验收矩阵

- 规则：无重复牌、无非法状态、计分与规则文档一致；
- 隐私：任何快照都不暴露其他手牌或牌库顺序；
- 体验：快速局约 12–18 分钟，核心行动无需打开二级页面；
- 弱网：普通网络重连后 3 秒内恢复；
- 设备：至少两台 iPhone、两台 Android，窄屏与长屏均不遮挡核心按钮；
- 性能：目标设备保持不低于 30 FPS；
- 视觉：最终 Design QA 无 P0/P1/P2 问题。
