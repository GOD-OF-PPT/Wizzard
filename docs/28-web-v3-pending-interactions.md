# 2026-10-19 联网动作待应答交互

目标仍active，整体视觉验收blocked。本批修复实际交互缺口：网络适配器原本保留pending命令、阻止重复发送，但界面仍显示可点击的确认动作，用户无法判断是否正在提交。

## 合同与实现

- `NetworkMatchAdapter`向`MatchUpdate`暴露pendingIntent。首次提交立即通知视图；无关快照、计时刷新和重连保留pending。只有匹配命令的权威ACK或匹配请求错误清除。发送返回不是结算成功，不预先移除牌、不推进轮次。
- Hook把该状态传给MatchScreen。出牌中保留选中牌，禁用手牌及确认，显示“出牌中”与aria-busy。预测中保留原值，禁用加减/确认以及方向键修改，显示“提交中”。选王牌禁用四个目标并显示等待文案。返回首页继续走原有本地/联机离开合同。
- DEV样例可用`pending=on-submit`从真实点击切入等待；这只是排版/控件验收，不发送服务端命令。生产构建应排除此夹具。

## 验证与边界

- Web适配器公开事件边界2项测试通过：重复提交只发一条；无关ACK/重连不解锁；匹配ACK和匹配拒绝解锁。这不是旧Cocos测试的替代声明，也不是线上传输全链路验证。
- Chrome390×694：预测点击增加两次再提交，值2，三个按钮禁用；对返回按钮按ArrowRight冒泡到面板后值仍2。截图`28-bid-pending-portrait-20261019.jpg`。
- Chrome出牌样例：选青叶5、确认后仍恰好该牌选中，手牌全部禁用，动作出牌中且aria-busy=true。截图`28-play-pending-portrait-20261019.jpg`。
- 选王牌等待文案首版压手牌，已移到面板下方与可见牌之间的空隙，字号3cqw/1.2行高；截图`28-chooser-pending-portrait-20261019.jpg`。手牌group几何包含旋转前空区，不能仅凭group矩形重叠判定可见牌被遮挡；实际牌面仍需各数量进一步检查。
- 当前尚无真实延迟ACK/断线恢复后的本批Chrome证据，继续列未完成；不把冻结样例与适配器测试合称真实联机通过。
