# 关键决策记录

## ADR-001：使用横版 16:9

状态：Accepted

3–6 人同时需要座位、中央牌墩和底部手牌。横版能保持八张以上手牌可读，并给左右玩家留出稳定位置；微信小游戏也更容易锁定横屏游戏画布。

## ADR-002：选择“奇术茶馆”视觉方向

状态：Accepted

用户选择了视觉探索中第二张生成结果。后续所有牌桌、卡面、头像和 UI 资源必须以 `public/assets/selected-art-direction.png` 为视觉真值。

## ADR-003：好友体验优先

状态：Accepted

首版面向固定好友，不做商业化、公共匹配或运营系统。优先级依次为规则正确、邀请顺畅、AI 补位、断线恢复和牌桌反馈。

## ADR-004：微信小游戏优先

状态：Accepted

当前视觉需要全屏横版牌桌、持续动画和复杂手牌布局。小程序虽然更适合普通 Web 式页面，但完整实现时需要额外维护页面组件与 Canvas 两套体系；微信小游戏与 Cocos Creator 2D 能用一套场景、输入和动画体系完成全部功能，因此正式客户端选择微信小游戏。纯规则层、协议与服务端继续保持平台无关。
