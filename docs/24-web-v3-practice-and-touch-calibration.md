日期：2026-10-18。目标仍 active；本文不是全页面像素验收通过声明。

## 练习新会话

Web 原实现固定使用种子 1，进入和重赛重复同一牌序。现在由 `src/web/practice-session.ts` 只负责会话熵和首手呈现策略，实际创建、发牌、规则与快照仍全部调用 `@wizzard/game-core`。

- 默认每次进入/重赛使用新种子。第一页生命周期内共享已显示首手记录，按可见面值而非实体卡 ID 防止相邻重复；最多尝试 16 个候选，不能无限循环。
- 显式注入 `seedSource` 默认精确重放；可显式打开防重复。生产没有种子 URL 参数或隐藏状态改写入口。
- 仅在 React commit 后记住首手，废弃渲染和 Strict Mode 探测不得污染“上次看见”的记录。
- Chrome 普通入口（无 fast/设计样例参数）连续八次真实进入/返回：首页依次看见青叶2、赭日12、靛山9、朱结3、青叶9、朱结2、青叶6、青叶11。相邻无重复。前两张证据为 `24-practice-entry0{1,2}-landscape-20261018.jpg`。
- 第九次普通练习首手朱结9，观察到第1–3轮结算后被开发服务整页刷新打断；不得将它称为完成八轮重赛验证。

窄范围既有 App/useLocalMatch 两文件 14 项通过，含默认新赛、显式重放、重绘不消耗种子、有界尝试及特殊牌副本可见面相同的回归；不替代 Chrome 视觉或真实流程。

## 竖屏密集手牌的两层问题

### 绘制顺序

原来 z-index 始终向右增大，选中中间牌时会把紧邻右牌夹在选中牌和更右牌之间。竖屏八张、选中青叶11后，靛山12的可命中面在 2px 采样网格中只有126点；向选中牌两侧分别递减叠放后为866点。不能把此前粗采样漏掉的小露出面说成完全不可见。

修复不改变卡牌尺寸、12px 抬升、9px 邻牌外移和右侧动作安全区。前后证据：`24-hand8-{blocked-portrait-before,unblocked-portrait-after}-20261018.jpg`。

### Chrome 原生触摸目标调整

最小触发：390×694，DEV `?design-review=gameplay&hand=7`，依次触摸青叶5、青叶11。落点约(203.436,566.279)的 DOM 可见目标为青叶11，但 Chrome 的原生 pointerdown/pointerup/click 全部送给赭日6，因此界面保留青叶5并显示跟色提示。这不是合法牌规则或 React 状态不同步。

已逐项排除：卡牌 hover 移位（鼠标移动前后目标一致）；双击缩放（已有 touch-action:manipulation，scale=1）；读帧过早（截图绘制屏障消除鼠标瞬态误读，触摸仍失败）。临时 `[DEBUG-touch-24]` 事件日志确认目标调整，修复后全部移除。

现在手牌组只针对 touch，在 pointerdown 捕获真实接触坐标下的可见牌 ID，正常 click 到来时选择该牌，而不是依赖 Chrome 调整后的相邻按钮。鼠标/键盘仍走原生按钮 click；pointercancel 清理，未生成 click 的滚动不选牌。非法牌仍调用原有合法性检查；选牌不发送出牌，确认才发送。

## 当前动效样式与完成帧

同一真实重赛的靛山8、root `data-reduced-motion=false`：一次输入后立即读到Y=-4.88879的过渡帧，transition为`transform 0.14s cubic-bezier(0.22,0.8,0.3,1)`，z30，halo矩阵Y=8；确认按钮实际出现`turn-action--pulse`，动画`0.56s … turn-action-pulse`。稍后读到卡牌Y=-12、零旋转，按钮class清除/animation=none。同一回合取消后再选，仍一个选中且不重播确认脉冲。证据 `24-selection-finish-live-landscape-20261018.jpg`。

这是当前浏览器实际计算样式、开始/结束状态与一次重复选择检查，不是连续帧视频或精密140ms/560ms实测时钟。当前Chrome接口拒绝Animation域，DOM只读桥也不提供getAnimations，未绕过限制；完整时间采样与多合法牌换选仍可进一步补充。
